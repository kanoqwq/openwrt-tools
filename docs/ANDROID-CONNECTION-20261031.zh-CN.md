# Android 无线连接与 OTA 重启修正

## 已确认的源码缺口

- Android ADB 把长命令的静默等待和连接失效共用了读取超时。在线缩容能力校验会等待内核完成工作，静默超过时限可触发 60 秒读取错误。
- 在线缩容曾将远程命令失败和无线断线都视为能力探测失败，可能错误提供清空数据的替代方案。
- Android ADB、SSH 原先跟随默认网络；手机同时连接无互联网的设备热点和蜂窝网络时，没有为目标的直连网段选择对应网络。是否为某位用户的实际超时原因仍需现场核验。
- OTA 的重启入口原先直接重启。设备默认回 Android 时，没有为这次补丁重启重新指定 OpenWrt 槽位。

## 修正行为

1. 长 ADB shell 命令每 5 秒产生随机标记心跳，读取端移除标记并记录“设备任务执行中”。传输空闲时限与命令总时限分离；持续心跳不会无限延长任务。命令仍在前台执行，原有退出码、二进制 dd/exec-out、真实缩容后台事务和断点恢复保持各自语义。
2. 在线 F2FS 同尺寸能力检查保留 600 秒总时限；只有完整返回的远程失败才进入能力失败处理。连接丢失先报告通信失败，恢复后按原事务复核，不自动清除数据或重放写入。
3. 手机端仅对目标 TCP socket 选择路由匹配的 Wi-Fi／以太网网络，按最长非默认前缀匹配，兼容 IPv4/IPv6；不绑定整个 App，不修改手机网络设置。目标不在直连网段时仍使用系统默认路由。
4. 共用 SSH 连接设置 TCP 连接时限、鉴权／banner／channel 时限及 15 秒保活；上传完成后的退出状态也有时限。超时或连接关闭不重试写入命令、不宣告成功。
5. OTA 重启先获取补丁锁和系统切换锁，按动态 A/B 角色找到 OpenWrt，校验试启动记录和现有记录的长度／格式／CRC，再仅写 misc 偏移 2048 的 32 字节并回读；写入失败尝试恢复原记录。不修改默认启动策略，也不挂载系统分区。确认返回后延迟 2 秒重启，子进程在此期间继续持锁。

## 验证及交付边界

测试覆盖心跳跨包分割、NUL 输出、总时限、实际静默 shell 和心跳清理；连接失败不误入擦除路径；路由绑定先于连接、IPv4/IPv6 和失败关闭；SSH 握手／上传／退出状态边界；两家族反向槽位、保留默认系统、CRC 拒绝、短写与错误回读恢复、重启锁及失败取消。

这些是离线测试，不等于手机无线环境或分区写入的实机验收。APK 重编只更新控制端；已安装的旧 LuCI OTA 插件和已导出的差异包不会自动获得新运行时，需要更新插件／固件或重新生成带新运行时的差异包。旧完整包自带的旧版 e5-update.py 也不会因安装新 APK 而自动替换；新的完整包包含 SSH 公共连接入口。
