# 同一 LZ4 流内的多段 CPIO 与 OTA 启动绑定

2026-11-13：F50 差分更新后主动返回 Android。更新事务已经完成，日志为
`tf-root-unavailable (returning to Android; eMMC root probe skipped)`。
系统分区和更新前备份均可读取，不是已确认的文件系统损坏或内核崩溃。

## 原因

有效 Linux initramfs 可以在同一解压流内包含多个 newc CPIO 归档，中间和
末尾允许 NUL 填充。重新压缩启动镜像会将原先分别压缩的归档合并到同一个
LZ4 流；内核仍会按顺序应用全部归档，后续记录覆盖基础记录。

原 `metadata()` 和 `entries()` 遇到第一个 `TRAILER!!!` 即停止读取整个流，
漏掉后续实际生效的 init、存储选择和槽位绑定。此次实机更新前的 boot 中，
TF 基础段含 `mu300-root-target=sd`，后续段含 `mu300-desktop-root-mode=part`。
旧解析器漏读后者，导致新版 boot 被错误绑定为 TF-only。

## 修改

- 读完每一条 CPIO 记录后继续处理后续归档，跳过归档间/末尾 NUL 填充。
- 按实际归档顺序保留后续覆盖值；同时修正流式元数据和通用归档枚举入口。
- 流式读取仍跳过不需要的模块正文，不将整份解压 ramdisk 常驻内存。
- 没有修改用户文件容错策略、OTA 文件清单验证、账户合并或无线配置保留。
- 公共运行时供 MU300、E5 与 Pro 使用；不是按机型、固件版本或文件哈希特判。

## 回归与实机

新增用例覆盖单一 LZ4 流内的多段归档、后段 init/存储覆盖、跨解压块头部、
大段 NUL 填充、MU300/E5 双向槽位绑定、重复更新及非法尾部。
OTA 全流程 20 项、Pro 三镜像与回退 22 项回归通过，包含已有的大模块内存约束。

实机使用本次失败 boot、事务原备份和目标包重做绑定。内核、模块、命令行
和持久故障日志均保留，只改 11 个 4 KiB 页；完整镜像哈希回读一致。
仅当原 journal 的 boot 签名精确匹配失败镜像时同步修复后的撤销签名，保留
原启动备份与原 journal，不跳过撤销冲突检查。用户已确认重新启动成功。

旧差分包自带旧运行时；需要使用包含本修复的安装器/生成器重新生成，
仅更新电脑外层入口或目标根里的插件不能替换旧补丁内嵌的解析器。
诊断备份与原始实机日志不作为公开构建输入或发布附件。
