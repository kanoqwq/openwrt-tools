# 系统补丁与网页差分生成恢复检查

2026-11-13，对公共 runtime 和实际 LuCI 视图进行离线检查；没有连接或改写实机。

## 确认并修复的问题

| 情况 | 原行为 | 修正后 |
| --- | --- | --- |
| 基准缺失、内容损坏或与当前版本不匹配 | 通用缺少基准提示；缓存可能继续隐藏初始化入口 | 分别显示原因，直接提供当前完整 ZIP 上传与初始化入口 |
| 缓存损坏、类型错误或缓存不可写 | 有效基准也可能不可用，部分类型错误中断整个状态请求 | 缓存可丢弃，重新验证真实基准；缓存写入失败不影响基准有效性 |
| 基准内容改变但长度和 mtime 保留 | 可能继续使用旧缓存，页面认为可用却生成失败 | 缓存键包含设备、inode、ctime、mtime、大小及当前固件身份；生成仍完整验证基准 |
| 基准判定有效但用户需要重建 | 初始化区隐藏，没有手动重建按钮 | 提供“重新初始化基准”，仍校验上传固件与当前型号、版本和内核是否相符 |
| 临时状态请求失败 | 生成区可能永久停留在禁用状态 | 提供“刷新生成状态”，不需要刷新整页，不新增空闲轮询 |
| 任务记录损坏 | 状态 RPC 失败，影响生成区甚至系统补丁状态 | 报告任务记录损坏并允许重新开始；不删除或重置更新事务 |
| 旧任务成功、新请求被拒绝 | 旧任务 ID 可能使新错误被忽略，甚至弹出旧包 | 每次任务有独立标识；明确区分请求拒绝、应答丢失与新任务完成 |
| 生成／校验应答丢失 | 可能误报失败，或把旧成功结果当成本次结果 | 查询同一实现的后台任务，核对新任务／校验票据，继续等待或报告失败；不重新发起任务 |
| 删除生成包已成功但应答丢失 | 显示删除失败，标题停在等待确认 | 查询实际文件状态，确认已删除后恢复正常状态；状态刷新成功也清除旧错误通知 |
| 后续生成失败或重新初始化基准 | 文件还在但任务记录已覆盖，下载／校验入口消失 | 单独保存最新成功包的摘要，任务状态和成功结果独立 |
| 成功包摘要丢失或损坏 | 有文件却无法获取 | 仍可下载或删除，提供完整只读校验，校验后依旧需要确认才能刷入 |
| 断电遗留生成目录 | 下次任务可能继续占用空间 | 取得任务锁后清理带本工具所有权标记的临时目录，不跟随目录符号链接 |

基准只来自干净完整固件或补丁中的目标版本摘要；不把用户修改后的 live root
采集成基准。没有加强整机一致性检查，现有配置、插件和系统文件小改动的兼容
规则保留。新旧 ZIP 的型号匹配、基准身份、包内哈希、实际刷入前的审阅 ID、
备份和恢复仍由原协议验证。

## 清理边界

生成失败不覆盖上一份成功包；成功生成才替换它。删除按钮只删除生成的包及
对应摘要。原始版本基准和更新恢复副本保留。异常退出后的自动清理只针对
`builder/.build-*` 下带 `unisoc-ota-builder` 标记的目录，且必须已取得互斥锁。
旧版本没有标记或无法确认归属的目录、备份和其他文件不会被自动删除。

## 回归方式

- `tests/test_ota_builder.py`：真实完整 ZIP、基准与缓存损坏、相同 mtime 的内容
  变化、任务记录损坏、重新初始化、失败后下载保留、摘要丢失后重新校验、
  临时目录所有权、删除互斥、更新和撤销后的基准恢复。
- `tests/ota_luci.js`：真实视图的 RPC 夹具，包括三种基准故障、手动重建、
  临时状态失败后刷新、旧成功结果不掩盖新错误、生成／校验应答丢失、
  无摘要包的下载、只读权限及空闲不轮询。
- `tests/ota_luci_browser.py`：直接加载本仓库当前 runtime，显式通过
  `OPENWRT_E5_SOURCE` 选择固件 CSS；检查 18 组响应式／主题／语言布局，
  18 组缺失／损坏／不匹配的初始化入口，以及有效基准的手动重建入口。
- `tests/ota_rpc_bus.py`：无网络临时 OpenWrt 容器，复现旧版大结果导致 rpcd
  登录对象掉线，并验证精简响应后对象保持正常。

最终检查通过 153 项 Python 回归、真实 LuCI 视图的 Node 回归、实际浏览器
布局及恢复入口检查，以及 rpcd/ubus 消息大小对照。未新增空闲后台任务。

设备刷写、重启和突然掉电需要另行实机验收；离线进程和文件系统夹具不冒充
已经完成这些硬件操作。
