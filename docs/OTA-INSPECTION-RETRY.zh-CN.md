# 检查失败后重试与 ZIP 时间戳修正

2026-11-19。

网页在发起新检查之前读取上一条检查记录，把正常返回的 `status=failed` 任务记录中的 `error` 当作本次 RPC 请求错误。上一次上传完整固件 ZIP 后，即使下方已经生成合法差分包，两个入口都不能开始下一次检查。只关闭通知或刷新页面无法清除持久化记录造成的阻断。

状态读取现在区分失败任务记录与 RPC 错误，保留新任务的真实失败、权限错误、票据替换检查和显式刷入确认。适用于上传入口和生成结果入口；不删除基准、生成包、检查记录或恢复副本，不放宽补丁兼容性或文件校验。

同时修正封装可复现构建产物的时间戳问题：部分输入文件 mtime 为 Unix epoch，原先 ZIP 封装会抛出时间早于 1980 年的错误。现在由 Python ZIP 实现将时间钳制到格式允许范围，内容与权限保持原样，不改源文件或其构建摘要。

回归包括：原机网页负对照、两个入口失败／损坏旧记录后的重试、正常／丢失回执、新检查失败停止轮询、权限拒绝和不自动刷入；完整 OTA Python 回归 204 项中 203 项通过、1 项因平台条件跳过；ZIP 时间边界与 macOS 执行权限 2 项通过。网页 Node 回归通过。

本机热修仅替换网页文件且保存原件，未重启机器或 rpcd，未刷入补丁。设备诊断与备份不纳入源码。正式包必须重新收录此运行时源码，并按原流程校验安装器产物的源指纹，不能复用指纹过期的程序或手改 build.json。
