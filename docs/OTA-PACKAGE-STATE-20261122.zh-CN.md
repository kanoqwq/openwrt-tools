# 旧执行器更新后的包数据库残留

现场已更新至新完整包对应版本，kernel 行已经恢复基础发行版记录，但仍有
28 条 `origin=unisoc-native-kernel` 的生成式 kmod 记录和旧 world 约束。
实际差分包携带的 RAM engine 与旧 `760aa26` 一致；新 engine 虽已安装到磁盘，
并未参与这次正在运行的合并。此前只验证干净目标数据库的验收不充分。

## 修正范围

- 按生成记录本身的 origin、版本和 kernel 依赖识别本工具的旧记录，允许
  kernel 行已恢复的中间状态。不删除驱动文件，不限制固件版本或内核 ABI。
- 只移除同批生成版本中、已被正确记录替换却仍残留的 world 约束；保留真实
  用户 kmod、软件源标签、其他版本约束及用户自行升级的软件。
- 差分包在已有哈希 runtime 中携带目标包数据库和 world。即使两个干净完整包
  的包状态相同，仍能完成现场遗留迁移。仅在确认存在本工具生成的残留时补做
  相应元数据操作，并走原事务备份与回滚；无关元数据保持原样。
- 保持旧 manifest 格式、校验及启动入口。执行器仍属于生成工具，不假定尚未
  更新的旧工具会自动获得新逻辑。首次过渡应使用本次修正版 Diff Studio 生成
  OTA，再通过原导入入口执行。只用旧网页生成的桥接更新可先更新工具；随后
  必须用更新后的工具针对另一新目标版本生成，不能重复刷同一个目标版本。
