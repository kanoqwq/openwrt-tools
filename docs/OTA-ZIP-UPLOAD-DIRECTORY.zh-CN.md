# 完整 ZIP 上传前建立接收目录

2026-11-14。用户反馈 V50 在“导入当前版本完整 ZIP”阶段出现
`2,No such file or directory` 和 `Upload request failed: Failed to open target file`。
截图能够确认上传目标打开失败，尚不能单凭截图确定用户机器缺失的具体路径。

核对当前 LuCI 的 `ui.uploadFile()`：它把固定目标路径交给 `cgi-upload`，
不会创建父目录。原页面只依赖打开时的 `build_status` 请求创建
`/etc/unisoc-ota/builder`；页面保留期间目录缺失后，点击上传不会重新准备。
另外，RPC 返回的 `{error: ...}` 被当作普通状态，可能错误地启用上传按钮。

修正沿用现有后端，不增加常驻服务或轮询：

- 每次上传当前、旧版或新版完整 ZIP 前，先调用 `build_status`。
  后端原有 `Builder` 构造函数以 `parents=True, exist_ok=True` 建立固定目录，
  新目录权限为 `0700`。目录不存在时自动创建，不要求用户手动执行命令。
- 状态中的后端错误正常抛出，创建失败时不进入文件上传；错误原文保留。
- 若此时已有生成任务，不覆盖它正在使用的 ZIP。准备过程中禁止重复点击。
- 保留原有符号链接检查，不删除阻挡目录的任意文件，不改版本校验、
  已有基准、生成结果、恢复副本或用户配置。

离线回归使用真实临时目录模拟 CGI 的直接打开操作，覆盖页面打开后目录被移除、
三个 ZIP 入口、RPC 返回错误、断联、重试、重复点击和生成任务并发。
RPC 测试直接调用生产分发器，分别验证 MU300、Pro、E5 创建目录及再次补建。
这是代码与离线复现的修复，未对反馈用户的设备进行部署或硬件验收。
