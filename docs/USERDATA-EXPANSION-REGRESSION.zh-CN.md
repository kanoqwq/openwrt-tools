# userdata 扩容追加回归（2026-10-31）

范围为公共安装器，同步覆盖 E5/MU300 的 Windows、Apple Silicon macOS、Android。未连接设备执行扩容、清空、刷 boot 或 NV；模拟器、临时普通文件和网页模拟桥不算硬件验收。

## 发现并修正

1. **Windows 设备脚本换行**：实际 Windows Python 写出的 `storage.sh`、`SHA256SUMS` 带 CRLF；此前 Linux 临时磁盘执行测试未能覆盖这个平台差异。新增测试先在 Windows 复现失败，再改为固定字节写入，避免 Android shell 或校验工具将 CR 当成文件名／语法的一部分。
2. **挂载源归属**：容量与 UUID 不足以单独证明 `/data` 属于 userdata。扩容计划、ext4 执行和最终核验都检查实际块设备：原始源必须就是 userdata；dm 源的底层必须唯一指向该分区。指向其他分区或不明确的多层映射不进入保数据或清空计划，显式清空同意也不能绕过这项身份检查。
3. **断线后的扩容进程**：ext4 改为本事务专用脚本，重连时检测脚本及本事务的原生 resize2fs 进程。即使父 shell 已退出、resizer 成为孤立进程，仍不能重复启动或提前报完成。其他事务／无关的 resize2fs 不会被误拦截。收尾删除本事务脚本，保留可管理的恢复备份。
